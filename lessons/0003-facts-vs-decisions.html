AI Lesson · Stage 1

Lesson 0003 · Facts vs Decisions

单一目标：面对 grilling 中的一个问题，判断它应该由 AI 自查，还是由用户做决定。

上一课：Decision Frontier 速查：Facts / Decisions 课程地图
本课完成标志

你能把事实问题交回 AI 调查，把真正的取舍问题留给用户；遇到“事实 + 决策”混合问题时，能先拆开再处理。

1. 两种完全不同的问题

Fact：环境中已经存在一个答案，AI 应该去发现它。
Decision：答案取决于目标、偏好、风险或授权，需要用户选择。

Fact “当前 main 分支最后一次提交是什么？” → 查 GitHub / git Decision “这次是否允许直接向 main 提交？” → 用户决定

关键不是“AI 知不知道答案”，而是答案是否已经客观存在于环境里。如果能通过仓库、文件、代码、日志、工具或搜索得到，AI 不应该把调查工作转嫁给用户。

2. 一个非常实用的判断法

这个问题如果换一个人来查， 在同一环境下会得到同一个答案吗？ 通常会 → Fact → AI 去查 不一定 → Decision → 用户选择

3. 最容易出错的是“混合问题”

AI 经常把 fact 和 decision 粘在一句话里：

“现在项目有没有自动部署？如果没有，要不要加？”

这其实是两个问题：

① Fact：现在有没有自动部署？ → AI 自查 ② Decision：在已知现状后，要不要增加自动部署？ → 用户决定

不要让用户替 AI 查事实；也不要让 AI 偷偷替用户做取舍。

4. Fact 还没查完时怎么办？

如果某个 decision 依赖一个尚未查明的 fact，这条分支暂时不能继续。但整个 grilling 不需要停住：其他不依赖这个 fact 的 frontier 问题仍然可以继续问。

Fact F1：现有系统是否支持回滚？ ← AI 调查中 └─ Decision D2：是否采用自动回滚？ ← 等 F1 Decision D3：发布是否需要人工批准？ ← 与 F1 无关，可现在问

5. Retrieval practice

Q1. “当前项目使用哪个 CI 配置？”
Q2. “新功能是否必须支持离线运行？”
Q3. “目前有没有自动部署；如果没有，要不要加？”第一步？

6. 一句话记忆

事实由 AI 发现，决策由用户选择；混合问题先拆开，事实先行。
