Lesson 0001 · Skill 与 Flow

单一目标：面对一个工程任务时，先识别它所处的工程阶段，再选择 Skill，而不是先背 Skill 名称。

速查：Skill / Flow 地图 课程地图
本课完成标志

你能用自己的话区分 Skill 与 Flow，并在简单场景中知道应该先判断工程阶段。

1. Skill 是具体能力，Flow 是整体路径

Matt 将这些 skills 设计成小、可组合、可修改的工程能力，而不是接管整个开发过程的大框架。不同 Skill 解决不同失败模式；Flow 则把它们按任务阶段组合起来。

Skill = 针对某类工程问题的独立能力。
Flow = 多个 Skills 按工程阶段形成的整体工作路径。

2. 不要从 Skill 名称开始思考

真实任务 ↓ 现在处于什么工程阶段？ ↓ 当前缺的是：决策、证据、规格、实现、诊断还是审查？ ↓ 选择对应 Skill ↓ 必要时进入下一阶段的 Skill

例如，一个需求边界仍然模糊时，问题不是“哪个 Skill 最强”，而是“现在还没对齐设计，所以不该直接实现”。当某个设计问题必须真正跑起来或看见效果才能回答时，才需要 prototype。
