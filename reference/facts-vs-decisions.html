Facts vs Decisions

Grilling 中最重要的责任边界之一。

Fact = AI 去发现。Decision = 用户来选择。

快速判断

答案已经客观存在于环境里？ ├─ 是 → Fact → 查代码 / 仓库 / 文件 / 日志 / 工具 / 搜索 └─ 否 → Decision → 需要目标、偏好、风险或授权 → 问用户

常见类型

“当前默认分支是什么？” → Fact “是否允许直接提交 main？” → Decision “现在有没有 CI；没有的话要不要加？” → Mixed ├─ 先查 Fact └─ 再问 Decision

与 Decision Frontier 的组合

Fact F1：AI 正在调查 └─ Decision D2：依赖 F1 → 暂停这条分支 Decision D3：与 F1 无关 → 仍在 frontier，可现在问

监督 AI 时看三种错误

错误 1：把事实甩给用户。
“你们仓库现在有没有测试？”——如果 AI 有仓库访问，就应该自己查。

错误 2：替用户做决定。
“我决定以后所有 ticket 都自动并行。”——这属于策略取舍，未经授权不能暗填。

错误 3：把混合问题一起问。
先查客观现状，再基于查到的事实提出真正的 decision。
