grill-with-docs Orchestration Map

用于快速监督：入口是否正确、两个依赖是否都加载、哪些结果真正落盘。

调用链

用户主动 /grill-with-docs ↓ Skill tool call #1 → grilling design tree / frontier / facts / shared understanding + Skill tool call #2 → domain-modeling terminology / scenarios / code cross-check / durable docs ↓ stateful alignment in a repo

Paper trail

resolved term → CONTEXT.md，立即写 qualifying hard decision → docs/adr/NNNN-*.md ordinary decisions → conversation only → 后续在同一会话交给 to-spec

路由

无 working directory / 不写文件 → grill-me 有 repo + 单会话可澄清的 fuzzy change → grill-with-docs 工作大到单会话装不下 → wayfinder

监督失败模式

只加载 grilling：问题问得很好，但 CONTEXT.md/ADR 从不更新。

只做 domain-modeling：可能记录词和决定，但没有完整 design tree/frontier 对齐。

把所有答案写进 CONTEXT.md：把 glossary 变成 spec，错误。

会话结束后清空上下文：普通 decisions 没有持久化，会丢；应把同一会话继续交给 to-spec。

监督口诀：两个 Skill 都加载；术语即时落盘；ADR 少而精；其他决定留在会话并继续传给 to-spec。
